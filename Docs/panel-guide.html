GTReview · 3D Slicer extension

What every control in the panel does

The module panel has four sections, and you work down them in order: Dataset picks the case, Display sets up what you see, Lesions lists what there is to check, Editing changes it. A fifth, Recording, is optional and runs alongside the other four. Each control below is named exactly as it appears on screen.

Dataset

Points the tool at a batch of cases and decides which mask you are correcting. Nothing here changes a mask on disk except Delete review; loading a batch only adds GTReview's log file to it.

Batch directorypath + Browse & load…

The folder that contains the case folders — one level deep, so point at batch_01, not at its parent and not at a single case.

The dropdown remembers the last ten batch directories you opened.

Once cases are found in it, GTReview writes its log into this folder as GTReview.log, adding to it every session. Each session opens with a header naming the GTReview build, the Slicer version and the path of Slicer's own log. Then it holds:

  • GTReview's messages and errors with their tracebacks, and any uncaught error in GTReview's code;
  • warnings and errors from Slicer, VTK and Qt, a run of identical ones written once with a count. They are copied when Slicer's event loop runs again, so one can appear after GTReview lines logged later, and warnings from anything else open in Slicer can appear too;
  • the Python stack if Slicer crashes, except on Windows, where crash reports are off;
  • a Timeout (0:00:15)! block with the stacks when Slicer's main thread stays busy for 15 seconds. It shows where Slicer was stuck, which is not always GTReview (another module, a slow repaint, App Nap, waking from sleep), and has no time stamp: it belongs to the time of the lines around it.

Crash and freeze reports start only once a batch with cases is loaded; what was logged before waits in memory and is lost if Slicer crashes first. The log moves to GTReview.log.1 only when a session starts past 5 MB; within a session, past 5 MB, Slicer's warnings stop being copied. It holds folder paths and case ids and is never sent anywhere; when something goes wrong, send it, GTReview.log.1 if there is one, and the Slicer log its header names.

The file stays open while the batch is loaded. On Windows that keeps the folder from being moved, renamed or deleted: close Slicer or load another batch first.

Moves between cases. A ✓ after a case name means a review has already been saved for it. The counter on the right is your position in the filtered list.

Skip already reviewed casescheckbox

Hides every case that already has a saved review, so Next walks only the work that is left.

Mask sourcedropdown

Which mask of this case you are reviewing — typically seg, or pred_seg where there is no ground truth yet. If a review was saved earlier it is offered here too, so you can pick up where you left off.

Delete reviewbutton

Removes this case's <case>_reviewed_seg.nii.gz from disk and reopens the case from its original mask. Greyed out when there is no saved review.

This is the one control undo cannot reach. It deletes a file. It names the file and asks first, and any unsaved edits in the editor go with it.

The file listread-only

Under the controls, the case's files with their short keys — t1c, pred_seg, seg. The dot marks the one currently loaded. The greyed path below is the case folder.

Display

Everything here changes only what reaches your eyes. No control in this section can alter a voxel.

Imagedropdown

Which sequence sits underneath the mask. Also the image the intensity-based tools read, so switching it changes what Sphere threshold measures.

Compare with · Blenddropdown + slider

A second sequence faded over the first — t1c over flair, say. Both rows stay hidden for a case with only one sequence, which is most of them.

Contrastwindow / level

Brightness and contrast of the image. Auto follows the volume; Manual lets you drag the range or type W and L. The … button holds the modality presets.

Layoutdropdown

Four-Up, 1×1 Red (axial), 1×1 Yellow (sagittal), 1×1 Green (coronal), 2×2 slices, or Conventional. One slice filling the window is usually the fastest way to paint.

Slices: align to the image gridcheckbox · on by default

Rotates the slice views onto the mask's own voxel axes.

In this data the mask sits a median 8.3° off the anatomical axes, so the ordinary axial/coronal/sagittal planes cut the voxel grid diagonally — and a stroke you draw as a clean disc is committed as a stair-stepped one. Untick it when you want true anatomical orientation to judge anatomy.

Mask: show + slidercheckbox + opacity

Hides the mask or fades it, so you can see the underlying tissue you are deciding about. On the keyboard: s hides and shows, a and d step the fill 10% either way.

Reset field of viewbutton

Re-centres and re-fits every slice view on the volume. The same thing r does with the pointer over a view.

Lesions

Every connected component of the current mask, recomputed as you edit. This list is your worklist: the case is not finished until each row is ticked.

New lesiontoggle button

Arms the brush over empty mask. Paint anywhere nothing is labelled and the stroke becomes its own row once the list refreshes. It uses whatever Active label is set to. Esc cancels.

#column

A rank by size — not a name. Numbers are handed out afresh on every recount, so a lesion's # changes when another lesion is painted, deleted, or grows past it. Your Done ticks are tracked by position in the volume, not by number, so they survive the renumbering.

Voxels · Volume (mm3)columns

Size of the component, in voxels and in physical volume. Click either heading to sort; the list opens sorted by size, largest first.

Donecheckbox column

Your record that you have looked at this lesion and are happy with it. Save & next case stays disabled until every row is ticked.

🗑per-row button

Deletes that whole lesion — every one of its voxels, from every label. It asks first, naming the voxel count, and it is undoable with Ctrl+Z. Nothing is written to disk until you save.

Selecting a rowbehaviour

Jumps every slice view to that lesion's centre and briefly flashes it, so you can tell which of several nearby components you have. The centre is snapped to a voxel that is genuinely inside the lesion, so it never lands in a hole.

Selecting a row is also what unlocks the brush — see Editing.

The summary lineread-only

3 lesions | 4059 voxels | 4059.0 mm3 | 0/3 done — the whole case at a glance. The done count turns green when the case is ready to save.

Editing

Two questions before any tool: which label goes down, and what it is allowed to paint over. Then the tool itself.

Undo · Redo · Resetbuttons

One press is one operation — a whole brush stroke, a lesion delete, a threshold apply. Reset is different: it reloads the mask from disk and discards everything since your last save.

Active labeldropdown

What the brush lays down:

  • 1 - Necrosis and Cavity
  • 2 - Enhancing Tumor
  • 3 - Edema
  • Background (erase) — painting background is erasing, so choosing it arms the Erase tool.

It follows the lesion you select. After that it stays on whatever you choose, whichever tool you pick, by button or digit key.

Brush: Live fillcheckbox

Ticked (default): the mask fills under the brush as you drag. Each stamp is committed on its own, which costs a few milliseconds on a large volume, so a long fast drag can feel stuttery.

Unticked: the drag only draws the brush outlines and the whole stroke is filled once when you release. Much smoother; you just do not see the fill until the button comes up. Undo treats a stroke as one step either way.

Unticked also stretches the undo history: Live fill saves one undo state per brush stamp, delayed paint one per stroke. The history is held to a memory budget, so on a large mask the oldest states are dropped first, and fewer states per stroke means more strokes to step back through.

Paint overdropdown

Which voxels the brush may change:

  • All labels — overwrite anything.
  • Background only — never touch a voxel that already has a label, so you can fill a gap without eating its neighbour.
  • Only 1 - … / Only 2 - … / Only 3 - … — only that label may be painted over.

It applies to all three tools, threshold included.

None · Paint · Erase · Sphere thresholdtool row

The tools, on 1 2 3. Each one's settings appear directly underneath.

Painting applies as the cursor moves rather than waiting for the mouse button, so what you see under the brush is what is committed.

The brush is locked until a lesion is selected, or until New lesion is armed. That is deliberate: it stops a stray click landing somewhere nobody is reviewing.

Sphere thresholdtool

Click the centre of a lesion and drag outward. A circle follows the pointer; release, and every voxel inside the sphere whose intensity is close to the one you clicked is added — in one undo step.

  • Tolerance — how far an intensity may deviate from the clicked voxel, as a percentage of it.
  • Include — similar to the seed, or additionally everything brighter / darker than it.
  • Only voxels connected to the seed — leaves unrelated bright spots inside the sphere alone.
  • 2D: this slice only — a disc on the slice you drew on instead of a ball through the ones you are not looking at. Use it when a lesion is only convincing on one slice.
Save & next casebutton

Writes <case>_reviewed_seg.nii.gz next to the case and opens the next one. Ctrl+S saves without moving on.

Disabled until every lesion is ticked Done — hover it and the tooltip says how many are left. The original mask is never modified; the review is always a new file.

Recording

Optional. Talk through the review and keep the views on video, so whoever listens or re-annotates later knows which lesion you meant at every moment. With both buttons off nothing here does anything.

Record microphone · Record videobuttons

Two switches, one at a time: the video records the microphone too, as its sound, so while one is on the other is greyed out. The one on pulses red and reads ■ Stop microphone or ■ Stop video; a red ● REC shows in Slicer's status bar and the time runs next to the buttons. Press again to stop; a few seconds later the panel says what it saved.

A recording starts by announcing the lesion you have selected. With none selected, as when a case has just loaded, it selects lesion 1 for you, as a click would, so the first lesion you talk about is named too. The same happens when a recording carries on into the next case.

Each case keeps one recording of each kind, in a folder of its own, GTReview-recordings/<case>/ with microphone/ and video/ in it, inside the batch folder (in your home folder if the batch folder cannot be written). Recordings made before, kept all in one folder, move into their case's folder when the batch is loaded. Moving to another case saves the one you leave and starts the next one's, without a gap. Recording a case that already has one asks first: Replace records a new one, which takes the old one's place once it is saved; Keep it leaves it alone. Moving on to a recorded case while recording asks the same, or stops. Open folder shows them.

Every switch to another lesion is logged with the lesion number and a voxel inside it. The number alone would not do: it is a rank by size and changes when lesions are deleted or grow, the voxel does not.

Microphonedropdown · Test

The input to record. System default follows whatever the system uses; the others are the microphones found, by name. Plugged one in? Press the refresh button next to the list. The choice is remembered, and the video uses it too.

Test opens the microphone for ten seconds and moves the level bar underneath, without saving anything. Speak: if the bar does not move, it is the wrong input.

Unplug the microphone while recording and its recording stops, with a warning; what it had recorded is kept, and a video goes on without sound. (Otherwise the system would quietly carry on from another microphone.)

The recording is your voice with the lesions spoken in: a short chime and a voice saying “lesion three” wherever you moved to another lesion (“new lesion four” for one you just painted, “now lesion two” when a recount renumbered the one you are on). Your voice is turned down under the announcement, never cut. Paging quickly through the list announces only the lesion you stop on. The video's sound is the same.

Videodropdown

All views records the view area as laid out — every sequence side by side in Sequences (axial). Or pick one slice view; it is recorded with its slider bar, which shows the slice position. Can be changed while recording.

A banner across the top of the video names the case and the lesion you are on, with its number, label, size and voxel. The picture comes from Slicer's own views, not from the screen: other windows on top, a second monitor, nothing gets in.

The video is an MP4 at 10 frames a second, with the microphone (and the lesions spoken in) as its sound and one chapter per lesion. It needs ffmpeg: Get ffmpeg…, or Record video when there is none, downloads it into Slicer once (about 30 MB).

What is savedfiles

In GTReview-recordings/<case>/:

  • microphone/<case>.wav — your voice with the lesions spoken in, and a marker at every lesion change.
  • video/<case>.mp4 — the video, with the same sound and a chapter per lesion.
  • <case>.json next to each — every event in order, with times and the lesion's voxel: the record to re-annotate from.

While it records, a file named <case>_<date-time>.recording… grows next to them; a crash leaves it playable.

macOS: Slicer as downloaded has no permission to use the microphone. GTReview says so up front, and the video records without sound. Enable the microphone… shows the one Terminal command that gives this Slicer the permission: run it once with Slicer closed, and macOS asks the next time. Video works everywhere. Windows: desktop apps must be allowed the microphone, under Settings › Privacy & security › Microphone › Let desktop apps access your microphone; GTReview says so when the microphone cannot be opened.

A voice recording is personal data, and the video shows the scans: keep recordings wherever the batch itself may be kept, and agree on recording with whoever is recorded.

The loop, and the keys

What a case actually looks like from open to save.

  1. Open the batch once — Browse & load…, then tick Skip already reviewed cases.
  2. Take the first lesion from the list. The views jump to it.
  3. Look before you touch. s hides the mask, a and d fade it — decide whether the boundary is right against the image, not against the overlay.
  4. Correct it if it needs it: paint, erase, or pull a threshold sphere. Ctrl+Z takes back whole operations.
  5. Tick it Done and move to the next row.
  6. Save & next case once every row is ticked.

GTReview is a scripted 3D Slicer extension. It reads your ground-truth masks and writes its output as a separate _reviewed_seg.nii.gz beside each case — the files you point it at are never modified.
